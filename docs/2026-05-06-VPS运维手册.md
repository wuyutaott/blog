## 占位符约定

文档中出现的 `${VPS_IP}`、`${VPS_HOST}`、`${DOMAIN}` 等占位符对应运维敏感值，真实值存放于项目根的 `.env` 文件（已加入 `.gitignore`，不进版本库）。

执行下文中含占位符的命令前，先在 shell 中加载：

```bash
source .env
```

加载后所有 `${VPS_HOST}`、`${VPS_IP}` 等在命令里会被自动替换为真实值。

完整的环境变量清单见项目根 `.env.example`。

## 1. 当前生产架构

```
用户浏览器
   │  HTTPS
   ▼
Cloudflare（CDN + WAF + DDoS）
   │  HTTPS (Full strict, Let's Encrypt 证书)
   ▼
VPS（${VPS_IP}, LAX）
   ├── ufw: 22 全开（Anywhere）+ 80/443 仅 CF IP（44 条规则）
   ├── fail2ban: 防 SSH 暴力破解（5 次错密码 → ban 1h）
   ├── unattended-upgrades: 每日自动安全补丁
   ├── Caddy（自定义编译，带 cloudflare DNS plugin）
   │   ├── 监听 80/443
   │   ├── 自动 HTTPS via DNS-01（再也不用碰证书）
   │   └── 当前路由：占位 "Hello World" + cdn.${DOMAIN} 静态资源
   └── 仅 SSH key 登录（密码登录已禁用）
```

## 3. API Token 和密钥状态

⚠️ **永远不要把 token 明文写进任何文档**。本节只记录 token 的"位置 + 权限 + 何时过期"。

### 3.1 Cloudflare User Token（VPS 用）

- **权限**：仅 `Zone:DNS:Edit`，限定单个 zone `${DOMAIN}`
- **TTL**：建议 7 天滚动续期
- **保存在哪**：VPS 的 `/etc/default/caddy` 文件里 `CF_API_TOKEN=...`
- **作用**：Caddy 用它做 DNS-01 challenge 自动续签 TLS 证书
- **若过期**：Caddy 续签会失败 → 站点逐步走向 cert expired

### 3.2 Vultr Personal Access Token

- **权限**：root（创建/管控所有 Vultr 资源）
- **客户端 IP 白名单**：必须包含执行端 IP（包括 AI agent 的出口 IP）
- **使用原则**：用完立即 revoke，不长期保留

### 3.3 Hetzner API Token

- **使用原则**：用完立即 revoke，不长期保留

## 4. 一行命令 cheat sheet

> 执行前先 `source .env` 让占位符生效

### SSH / 文件

```bash
ssh ${VPS_HOST}                          # 进 VPS
scp file.txt ${VPS_HOST}:/root/          # 上传文件
scp ${VPS_HOST}:/var/log/x.log .         # 下载文件
ssh -L 8080:localhost:8080 ${VPS_HOST}   # 端口转发
```

### Caddy 操作

```bash
ssh ${VPS_HOST} 'systemctl status caddy'                          # 状态
ssh ${VPS_HOST} 'systemctl restart caddy'                         # 重启
ssh ${VPS_HOST} 'caddy reload --config /etc/caddy/Caddyfile'      # 热重载
ssh ${VPS_HOST} 'journalctl -u caddy -n 50 --no-pager'            # 看日志
ssh ${VPS_HOST} 'journalctl -u caddy -f'                          # 跟随日志
ssh ${VPS_HOST} 'tail -f /var/log/caddy/access.log'               # 看访问日志
ssh ${VPS_HOST} "ls /var/lib/caddy/.local/share/caddy/certificates/*/${DOMAIN}/"  # 证书路径
```

### 修改 Caddyfile（部署新站/路由）

```bash
ssh ${VPS_HOST} 'vim /etc/caddy/Caddyfile && systemctl reload caddy'
# 或者本地编辑后:
scp Caddyfile ${VPS_HOST}:/etc/caddy/Caddyfile && \
  ssh ${VPS_HOST} 'systemctl reload caddy'
```

### ufw（防火墙）

```bash
ssh ${VPS_HOST} 'ufw status numbered'                            # 查规则
ssh ${VPS_HOST} 'ufw allow proto tcp from 1.2.3.4 to any port 9000 comment "X"'  # 加规则
ssh ${VPS_HOST} 'ufw delete <number>'                            # 按编号删
```

### Cloudflare DNS（用 token 调 API）

```bash
# 先在本地 export CF_TOKEN=<your token>
curl -sS -H "Authorization: Bearer $CF_TOKEN" \
  "https://api.cloudflare.com/client/v4/zones/${CF_ZONE_ID}/dns_records" | jq    # 列所有
```

### 测试

```bash
curl -I https://${DOMAIN}            # 应返回 200
curl -k https://${VPS_IP}            # 应 timeout（IP 隐藏成功）
```

## 5. 续 CF Token 流程（重要！）

**TTL 7 天到期前必须做**，否则证书续签失败。

```
1. 浏览器打开 https://dash.cloudflare.com/profile/api-tokens
2. 找到 caddy 用 token → 右边 "..." → "Roll"（或者直接 Create 新的）
3. 创建参数:
   - Permissions: Zone:DNS:Edit
   - Zone Resources: Specific zone → ${DOMAIN}
   - Client IP Filtering: ⚠️ 留空（若加了 VPS IP 不在白名单会签证失败）
   - TTL: 7 days from now（推荐）
4. 复制新 token
5. SSH 更新 + reload:
   ssh ${VPS_HOST} 'sudo tee /etc/default/caddy > /dev/null <<EOF
   CF_API_TOKEN=<新 token>
   EOF
   chmod 600 /etc/default/caddy
   chown root:caddy /etc/default/caddy
   systemctl restart caddy'
6. 验证: ssh ${VPS_HOST} 'journalctl -u caddy -n 10 --no-pager'
   看到 "certificate obtained successfully" 就成
```

## 6. 开通过程的复盘

### 6.1 时间线

| 阶段 | 事件 |
|---|---|
| 起 | 调研云厂商排名、对比 Hetzner / Vultr / AWS |
| 中 | 开始部署：先选 Hetzner（更便宜） |
| Hetzner KO | Hetzner Cloud 后端整体 service unavailable，机器卡 5 分钟+ |
| 切 Vultr | 删除 Hetzner 机器（未启动未计费）→ 切到 Vultr |
| Vultr OK | 5 分钟开通 vc2-1c-1gb at LAX |
| 加固 | 自动跑加固脚本（ufw / fail2ban / unattended-upgrades / 关密码登录） |
| Caddy 装 | 下载 caddy with cloudflare DNS plugin → systemd 跑 |
| 第 1 次失败 | CF token IP filtering 把 VPS IP 挡了，Caddy 签证失败 525 |
| 重生 token | 重新创建无 IP 限制的 user token |
| 第 2 次成功 | DNS-01 验证 → LE 证书签发 → https://${DOMAIN} 通 |
| ufw 收紧 | 80/443 仅 CF IP，直连 IP timeout（IP 隐藏成功） |
| 收尾 | SSH key 重命名 + ~/.ssh/config 加 ${VPS_HOST} 别名 |

### 6.2 关键决策

| 决策 | 为什么 |
|---|---|
| 切 Vultr 不再等 Hetzner | 等故障的不确定性 > 切厂的确定性 |
| LAX 不是 Hillsboro | Hetzner 美国节点没 CX 系列；Vultr LAX 离用户加州地址最近 |
| vc2-1c-1gb 起步 | 月 $5，levelsio 模式 90% 项目够；不够随时升 |
| Caddy with DNS-01 | 80 锁 CF IP 后 HTTP-01 续签会失败；DNS-01 不依赖端口 |
| SSH key 复用通用一份 | 私钥都在同一台 Mac，分开管理收益小，简化认知更值 |
| 不装 Tailscale | 没准备 Tailscale 账号，先把基础跑通 |

### 6.3 踩过的坑（避免重复）

1. **Hetzner 美国节点没有 CX 系列**——只有 CPX。要选 CX22 必须去欧洲。
2. **Hetzner 后端故障时 status page 不会及时反映 hil/ash 状态**——console 右下角红字"service unavailable"才是真信号。
3. **Vultr API 默认有 IP 白名单**——启用 API access 后必须先 add IP，否则写操作 401。
4. **Cloudflare API Token 的 "Client IP Filtering" 是杀手级坑**——Caddy 在 VPS 上调 CF API，VPS 的 IP 没在白名单里就 403。**写 Caddy 用的 token 不要加 IP 限制**。
5. **`cfat_` vs `cfut_` 前缀的 token 都能用**——一个是 Account 级，一个是 User 级；Edit zone DNS 模板默认创建 user token。
6. **CF token 在 zone 级权限不够调 `/user/tokens/verify`**——返回 invalid 是正常的，不影响实际使用。
7. **CF Proxy 开启时 LE HTTP-01 challenge 失败**——必须用 DNS-01 或者把 proxy 暂时关掉。
8. **screenshot 坐标 vs viewport 坐标要换算**：`viewport_x = display_x * (2056/2000)`。
9. **Hetzner IPv4 单独收费 €0.60/月**，不像 Vultr 包含。
10. **Hetzner 升级保留磁盘不可逆**——升过 80GB 就回不到 40GB 了；Vultr 同样限制。

## 7. 给 AI / 接手者的操作建议

### 7.1 凭 SSH 即可做的事

- 改 Caddyfile / 部署新路由
- 装 Docker / 任何 apt 包
- 写 systemd service / cron 任务
- 改 ufw 规则
- 看日志 / 调试
- 跑一次性脚本

### 7.2 需要 API token 的事

- **Vultr API token**：操作 instance（升级、删除、加新机）
- **Cloudflare API token**：改 DNS / WAF / 账户级配置（VPS 上的 token 仅 `Zone:DNS:Edit`，做不了 cache purge / page rules / WAF）
- **新机器的 root 密码 / SSH key**（如果不是从现有 VPS 复制）

### 7.3 永远先做的事

- 进任何会话前 **先读这份文档** 知道当前架构
- 改任何配置前先 `cp file file.bak.$(date +%s)` 备份
- 改 ufw 前确保 22/tcp ALLOW 还在（不然下次 SSH 不进来）
- 改 Caddyfile 前 `caddy validate --config /etc/caddy/Caddyfile` 测语法
- 改完 reload，不要 restart（除非证书或 listener 变了）

### 7.4 永远先确认的事

- 用户**有没有**给 API token？没有就让用户自己点界面或去生成 token
- 操作**会不会**扣钱？开机器、加付费功能（DDoS 防护、Backup）必须事先告知
- 用户**有没有**改 DNS 的需求？没有就别动

### 7.5 浏览器自动化辅助（browser-harness）

适用场景：Cloudflare dashboard / 云控制台等"必须点界面"的操作，且本机浏览器已登录该账号。

- **适合**：cache purge / page rules / WAF / OAuth 配置 / E2E 测试 / UI 调试
- **不适合**：API 能搞定的（更快更稳）/ 需要 2FA 现场输入的 / 长事务 / 反爬严格的站

判定顺序：
1. 先想能不能 API 解决（最快）
2. 不行再考虑 browser-harness（要本机浏览器配合）
3. 都不行再让用户自己点（最后选项）
